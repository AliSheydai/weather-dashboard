# Fix: Docker Compose Hot-Reload Not Working

## Root Cause

The project uses **production-only** Dockerfiles (multi-stage builds that compile code and run `node server.js` / `node dist/src/main`). There are **no bind mounts** for source code, so host edits are invisible to containers. Additionally, `next.config.ts` lacks webpack polling config needed for Docker on Windows.

## Plan

### 1. Create `docker-compose.dev.yml` — dev override with bind mounts

A new `docker-compose.dev.yml` that overrides the `frontend` and `backend` services for development:

- **Frontend**: bind-mount source code (`.:/app`), protect `node_modules` and `.next` with anonymous volumes, set `WATCHPACK_POLLING=true` and `CHOKIDAR_USEPOLLING=true`
- **Backend**: bind-mount source code (`./backend:/app`), protect `node_modules` with anonymous volume

**File**: `docker-compose.dev.yml` (new)

### 2. Create `Dockerfile.dev` for frontend — lightweight dev image

A simple single-stage Dockerfile that installs deps and runs `npm run dev` (Next.js dev server with HMR).

**File**: `Dockerfile.dev` (new)

### 3. Create `backend/Dockerfile.dev` — lightweight dev image for backend

A simple single-stage Dockerfile that installs deps and runs `npm run start:dev` (NestJS watch mode).

**File**: `backend/Dockerfile.dev` (new)

### 4. Update `next.config.ts` — enable webpack polling for Docker

Add `webpackDevMiddleware` config with `poll: 1000` so file changes are detected inside Docker containers on Windows (where `inotify` events don't propagate through the VM layer).

**File**: `next.config.ts` (modify)

### 5. Update `docker-compose.yml` — no changes needed

The existing `docker-compose.yml` stays as-is for production. Users run dev with:
```
docker-compose -f docker-compose.yml -f docker-compose.dev.yml up
```
