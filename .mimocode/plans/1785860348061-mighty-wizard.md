# Fix: Notification Dropdown Transparency Issue

## Root Cause

The notification dropdown is rendered **inline** inside the `DashboardHeader`, which has `backdrop-blur-xl` and `bg-white/[0.02]`. This creates a **compositing layer** where the blur is applied to the entire header's rendered output — including the dropdown. The dropdown's `bg-[#1a1a2e]` background gets composited with the blurred content beneath it, making it appear glass-like regardless of what opacity you set on the dropdown itself.

Additionally, the dropdown is nested inside two `overflow-hidden` ancestors (`DashboardLayout.tsx:24` and `:36`), which clip it.

**Key insight:** `backdrop-blur` on a parent element affects ALL child elements rendered within that compositing layer. Setting a solid background on a child does NOT override this — the blur happens at the compositing level, not the element level.

## Fix

**Use `ReactDOM.createPortal`** to render the notification dropdown at the `<body>` level, completely outside the header's compositing layer.

### File: `src/components/header/NotificationBell.tsx`

1. **Add portal import** at top of file:
   ```ts
   import { createPortal } from "react-dom";
   ```

2. **Replace the dropdown rendering** (lines 265-351): Wrap the `AnimatePresence` block with `createPortal(... , document.body)` so the dropdown escapes the header's stacking context and compositing layer.

3. **Keep `bg-[#1a1a2e]`** (fully opaque, already correct from previous edit).

4. **Optionally re-add `backdrop-blur-xl`** to the dropdown itself if a subtle blur effect is desired on the dropdown — now it will work correctly since it's no longer inside the header's compositing layer.

### Why this works
- Portal renders the dropdown as a direct child of `<body>`, bypassing the header's `backdrop-blur-xl` compositing layer
- The dropdown is no longer affected by `overflow-hidden` on DashboardLayout ancestors
- `z-50` on the dropdown now operates at the `<body>` stacking context level
