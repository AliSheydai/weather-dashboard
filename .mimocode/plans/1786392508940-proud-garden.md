# Plan: Interactive Hourly Time Slider with Data Fetching

## Goal
Make the hourly time slots in the TemperatureCard clickable and navigable via left/right buttons (slider-style). Selecting a time slot fetches precise data for that hour from the API and updates all side metric cards accordingly.

---

## Current State
- **Hourly strip** in `TemperatureCard.tsx` (lines 159-184): shows 8 time slots at 3-hour intervals, but they are display-only (no click handler, no selection state).
- **Backend `getHourlyForecast`** returns only `{ hour, temperature, condition, icon }` per entry — missing humidity, wind, visibility, rainfall, feelsLike needed by side cards.
- **Side cards** (`MetricsGrid`) currently derive their values from `daily[selectedDayIndex]` aggregated data, not from per-hour data.
- **OWM `/forecast` endpoint** already provides per-entry: `main.humidity`, `wind.speed`, `wind.deg`, `visibility`, `rain.3h`, `main.feels_like` — we just need to surface them.

---

## Implementation Steps

### Step 1: Extend Backend Hourly Response
**File:** `backend/src/weather/weather.service.ts` — `getHourlyForecast()` method (line 175)

Add the following fields to each hourly entry returned by the mapper (line 189-197):
```ts
{
  hour, temperature, condition, icon,
  humidity: item.main.humidity,
  windSpeed: Math.round(item.wind.speed * 3.6),
  windDirection: this.degToCompass(item.wind.deg ?? 0),
  visibility: Math.round((item.visibility ?? 10000) / 1000),
  rainfall: Math.round((item.rain?.['3h'] ?? 0) * 10) / 10,
  feelsLike: Math.round(item.main.feels_like),
}
```

No new endpoints needed — enrich the existing one.

### Step 2: Update Frontend Types
**File:** `src/stores/weatherStore.ts` — `HourlyData` interface (line 25)

Add the new fields:
```ts
interface HourlyData {
  hour: string;
  temperature: number;
  condition: string;
  icon: string;
  humidity: number;
  windSpeed: number;
  windDirection: string;
  visibility: number;
  rainfall: number;
  feelsLike: number;
}
```

### Step 3: Add `selectedHourIndex` State to HomeClient
**File:** `src/app/home-client.tsx`

- Add `const [selectedHourIndex, setSelectedHourIndex] = useState<number | null>(null);`
- Reset to `null` when `selectedCity` changes (alongside existing `setSelectedDayIndex(0)`).
- Reset to `null` when `selectedDayIndex` changes (different day = back to "current" view).

### Step 4: Update TemperatureCard — Selection + Slider Buttons
**File:** `src/components/weather/TemperatureCard.tsx`

**Props changes:**
- Add `selectedHourIndex: number | null`
- Add `onHourSelect: (index: number) => void`

**UI changes to the hourly strip (lines 159-184):**
- Wrap the strip in a container with left/right chevron buttons (`ChevronLeft`/`ChevronRight` from lucide-react).
- Left button: decrement `selectedHourIndex` (disabled at 0 or null).
- Right button: increment `selectedHourIndex` (disabled at last index).
- Each time slot: add `cursor-pointer` and `onClick={() => onHourSelect(i)}`.
- Highlight the selected slot with the indigo background (currently only index 0 gets it).
- When `selectedHourIndex === null`, index 0 ("Now") keeps its default highlight.
- When a slot is selected, show its temperature in the large display instead of the current temperature.

**Temperature display change:**
- When `selectedHourIndex !== null && selectedDayIndex === 0`: show `hourly[selectedHourIndex].temperature` and `hourly[selectedHourIndex].condition` instead of the current weather values.
- Animate the transition with the existing `AnimatePresence` (add `selectedHourIndex` to the motion key).

### Step 5: Derive Metric Values from Selected Hour
**File:** `src/app/home-client.tsx`

When `selectedHourIndex !== null`, derive metric values from the hourly entry instead of daily aggregated data:

```ts
const selectedHour = selectedHourIndex !== null ? hourly[selectedHourIndex] : null;

const dayHumidity = selectedHour?.humidity ?? selectedDay?.humidity ?? weather.humidity;
const dayWindSpeed = selectedHour?.windSpeed ?? selectedDay?.windSpeed ?? weather.windSpeed;
const dayWindDir = selectedHour?.windDirection ?? selectedDay?.windDirection ?? "NW";
const dayVisibility = selectedHour?.visibility ?? selectedDay?.visibility ?? weather.visibility;
const dayRainfall = selectedHour?.rainfall ?? selectedDay?.rainfall ?? 0;
const dayFeelsLike = selectedHour?.feelsLike ?? (isToday ? weather.feelsLike : Math.round(...));
```

UV index and AQI remain from the current weather (they don't vary hour-to-hour in the free OWM API).

### Step 6: Pass New Props Through Components
**File:** `src/app/home-client.tsx`

- Pass `selectedHourIndex` and `onHourSelect={setSelectedHourIndex}` to `<TemperatureCard>`.
- Temperature, condition, description, feelsLike props to TemperatureCard: override with hourly data when an hour is selected.
